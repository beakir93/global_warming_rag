# Мультимодальная RAG-система по глобальному потеплению
## Саммари проекта и материалы для защиты

---

## 📋 Краткое саммари

Это **мультимодальная RAG-система** (Retrieval-Augmented Generation), которая отвечает на вопросы о глобальном потеплении, используя:
- **Текстовую модальность**: расшифровка научно-популярного видео (транскрипция)
- **Визуальную модальность**: описания ключевых кадров из видео, полученные через GigaChat Vision

Система использует **гибридный поиск** (Dense + BM25 с объединением через RRF) и **HyDE-расширение запросов** для улучшения релевантности найденных документов.

## 🏗️ Архитектура системы

### 1. Подготовка данных (`prepare_data.py`)

| Этап | Описание | Инструменты |
|------|----------|-------------|
| **Скачивание видео** | Загрузка из YouTube через `yt-dlp` | `yt-dlp`, EJS-решатель для обхода JS-челленджей |
| **Извлечение кадров** | Нарезка видео на кадры с шагом 6 сек | `opencv-python` |
| **Описание кадров** | Генерация русскоязычных описаний каждого кадра | GigaChat Vision (GigaChat-2-Max) |
| **Чанкинг транскрипции** | Разбиение текста на фрагменты по 3 предложения с перекрытием 1 предложение | Собственная логика на regex |
| **Построение индекса** | Создание векторного хранилища с метаданными | Chroma + GigaChat Embeddings |

### 2. Поиск и генерация ответов

```
┌─────────────┐     ┌──────────────────┐     ┌─────────────────┐
│   Вопрос    │ ──► │  HyDE-расширение │ ──► │ Гибридный поиск │
│  пользователя│     │ (опционально)    │     │  Dense + BM25   │
└─────────────┘     └──────────────────┘     └────────┬────────┘
                                                      │
                    ┌─────────────────────────────────┘
                    ▼
┌─────────────────────────────────────────────────────────────┐
│                    RAG-генерация ответа                      │
│  • LLM получает контекст с тегами [T#] и [F#]               │
│  • Генерирует ответ со ссылками на источники                │
│  • Возвращает текст + превью кадров                         │
└─────────────────────────────────────────────────────────────┘
```

### Ключевые методы и алгоритмы

#### 1. Гибридный поиск (Hybrid Retrieval)
- **Dense-поиск**: косинусное сходство эмбеддингов запроса и документов в Chroma
- **Sparse-поиск**: BM25 по токенизированным документам
- **Объединение**: Reciprocal Rank Fusion (RRF) с параметром `k=60`
  ```python
  RRF_score = 1 / (k + rank)
  ```

#### 2. HyDE (Hypothetical Document Embeddings)
- LLM генерирует гипотетический ответ на вопрос (3–4 предложения)
- Гипотетический ответ используется как дополнительный поисковый запрос
- Улучшает поиск для абстрактных вопросов

#### 3. Чанкинг с перекрытием
- Размер чанка: 3 предложения
- Перекрытие: 1 предложение между соседними чанками
- Шаг: 2 предложения (3 - 1)

#### 4. Мультимодальность
- Документы помечаются метаданными: `modality = "text" | "frame"`
- Раздельные квоты на текст и кадры при поиске
- unified индекс с фильтрацией по модальности

#### 5. Цитирование источников
- Текстовые фрагменты: теги `[T1]`, `[T2]`, ...
- Кадры: теги `[F1]`, `[F2]`, ...
- Система принуждает LLM ссылаться на источники в ответе

## ❓ Типовые вопросы для защиты и ответы

### 1. Почему выбран именно гибридный поиск (Dense + BM25)?

**Ответ:** 
- **Dense-поиск** (векторный) хорошо улавливает семантическую близость, но может пропускать точные совпадения терминов, имён собственных, чисел.
- **BM25** (спарс) эффективен для поиска по ключевым словам, точным формулировкам, цифрам.
- **Комбинация через RRF** даёт лучшее покрытие: если документ релевантен хотя бы по одному методу, он попадёт в топ. RRF не требует нормализации скоров между методами.

---

### 2. Зачем нужен HyDE? Не проще ли искать сразу по вопросу?

**Ответ:**
- Вопросы пользователей часто бывают **абстрактными** или **слишком краткими** («Что будет с Арктикой?»).
- HyDE генерирует **гипотетический ответ**, который содержит больше контекстных слов и формулировок, близких к документам в индексе.
- Это улучшает **семантическое соответствие** между запросом и документами, особенно для Dense-поиска.
- Минус: дополнительный вызов LLM (~1–2 сек), поэтому сделан опциональным.

---

### 3. Почему именно GigaChat, а не OpenAI / другие модели?

**Ответ:**
- **Локальная доступность**: GigaChat — российская модель, работает без ограничений на территории РФ.
- **Мультимодальность**: одна модель поддерживает и текст, и vision, и embeddings — упрощает интеграцию.
- **B2B-интеграция**: стабильный API с предсказуемой стоимостью.
- **Качество на русском языке**: модель обучена с учётом русскоязычного контента.

---

### 4. Как обрабатываются ошибки при описании кадров?

**Ответ:**
В `captions.py` реализована **двухуровневая стратегия**:
1. Попытка загрузить изображение через `upload_file()` и передать по file_id (предпочтительный метод).
2. При ошибке — fallback на **base64-кодирование** изображения и передачу в `image_url`.
3. Если оба метода не сработали — запись заглушки `[caption unavailable: <error>]`.
4. **Кэширование**: результаты сохраняются в `captions.json` после каждого кадра, можно прервать и продолжить.

---

### 5. Как система гарантирует, что LLM не «выдумывает» факты?

**Ответ:**
- **System Prompt** явно указывает: «Отвечай строго на основе предоставленного контекста... Если данных недостаточно, честно скажи об этом».
- **Контекст с цитатами**: каждый фрагмент помечен `[T#]` или `[F#]`, LLM обязана ссылаться на них.
- **Ограниченный контекст**: модель видит только найденные документы, а не всю транскрипцию.
- **Температура 0.2**: снижает креативность, повышает детерминированность.

*Примечание: полностью исключить галлюцинации невозможно, но эти меры минимизируют риск.*

---

### 6. Почему чанкинг сделан по предложениям, а не по токенам/символам?

**Ответ:**
- **Семантическая целостность**: предложение — минимальная законченная мысль.
- **Удобство таймкодов**: легче сопоставить предложения с временными метками в транскрипции.
- **Предсказуемость**: 3 предложения ≈ 50–100 слов, что хорошо ложится в контекстное окно LLM.
- **Перекрытие в 1 предложение** сохраняет контекст между чанками без дублирования.

---

### 7. Как масштабируется система? Можно ли применить к другому видео?

**Ответ:**
- **Да**, достаточно:
  1. Положить новую транскрипцию в `data/transcript.txt`.
  2. Обновить `YOUTUBE_URL` в `.env` (или скачать видео вручную).
  3. Запустить `python prepare_data.py --force`.
- **Масштабирование**:
  - Chroma поддерживает персистентное хранение, но для больших объёмов лучше перейти на клиент-серверный режим.
  - Можно добавить **фильтрацию по коллекциям** для разных видео.
  - Для продакшена — заменить Streamlit на FastAPI + фронтенд.

### 8. Какие ограничения у текущей реализации?

**Ответ:**

| Ограничение | Последствия | Возможное улучшение |
|-------------|-------------|---------------------|
| **Транскрипция вручную** | Нет автоматической ASR | Подключить Whisper / GigaChat Audio |
| **Один индекс** | Нельзя искать по нескольким видео одновременно | Коллекции Chroma per video |
| **Streamlit** | Не подходит для high-load | FastAPI + React/Vue |
| **Нет кэша ответов** | Повторные вопросы обрабатываются заново | Redis / in-memory кэш |
| **Жёсткие квоты** | Фиксированное число текстов/кадров | Динамическое распределение по score |

### 9. Что будет, если токен GigaChat недействителен?

**Ответ:**
- При инициализации LLM/Embeddings/Vision будет выброшено исключение `AuthenticationError` (401).
- **Причины**:
  - Истёк срок действия токена.
  - Неправильный формат (должен быть Base64-строкой).
  - Токен отозван или не имеет нужных прав (`GIGACHAT_API_B2B`).
- **Решение**: получить новый токен в личном кабинете GigaChat B2B и обновить `.env`.

---

### 10. Как оценивается качество поиска?

**Ответ:**
- **Косвенные метрики**:
  - Релевантность ответов (субъективная оценка пользователя).
  - Наличие корректных ссылок на источники `[T#]`, `[F#]`.
- **Возможные метрики для тестирования**:
  - **Precision@K**: доля релевантных документов в топ-K.
  - **Recall**: сколько релевантных документов найдено всего.
  - **NDCG**: учитывает порядок релевантных документов.
- Для оценки нужен **размеченный датасет** (вопрос → релевантные чанки).
