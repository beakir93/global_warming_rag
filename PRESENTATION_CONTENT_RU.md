## СЛАЙД 2: Описание проекта

**Проблема:** Пользователям нужны точные ответы на вопросы о глобальном потеплении с опорой на источники

**Решение:** RAG-система, сочетающая текстовую транскрипцию и визуальные описания кадров

**Ключевые возможности:**
- Мультимодальный поиск: текст + изображения
- Гибридный ретривер: Dense (векторный) + BM25 (ключевые слова)
- HyDE-расширение запросов для абстрактных вопросов
- Загрузка пользовательских файлов (.txt, .md, .pdf)
- Обязательное цитирование источников [T#], [F#], [File#]

**Технологический стек:** GigaChat-2-Max, Chroma DB, LangChain, Streamlit

## СЛАЙД 3: Архитектура RAG-системы

**Схема пайплайна:**

```

│ • GigaChat Vision   │     │ • GigaChat       │     │ • HyDE расширение│
│ • Чанкинг           │     │   Embeddings     │     │ • Гибридный поиск│
│                     │     │ • BM25 индекс    │     │ • RRF объединение│
└─────────────────────┘     └──────────────────┘     └────────┬────────┘
                                                               │
                                                               ▼
┌─────────────────────────────────────────────────────────────────────┐
│                    4. Генерация ответа                               │
│                    • GigaChat-2-Max                                  │
│                    • Контекст с цитатами                             │
│                    • Температура 0.2                                 │

UI: Streamlit | Загрузка файлов (.txt, .md, .pdf) | Визуализация кадров
```

## СЛАЙД 4: Используемые модели и технологии

**LLM и мультимодальность:**
- GigaChat-2-Max — основная языковая модель
- GigaChat Vision — описание кадров видео
- GigaChat Embeddings — векторные представления

**Преимущества GigaChat:**
- Российская модель (работает в РФ без ограничений)
- Единый API для text/vision/embeddings
- Качественная поддержка русского языка

**Инфраструктура и библиотеки:**
- LangChain — оркестрация RAG-пайплайна
- Chroma DB — персистентное векторное хранилище
- rank-bm25 — спарс-поиск по токенам
- OpenCV — извлечение кадров из видео
- yt-dlp — загрузка видео из YouTube
- Streamlit — чат-интерфейс

## СЛАЙД 5: Этап 1 — Подготовка данных

**1. Скачивание видео**
- yt-dlp с EJS-решателем для обхода JS-челленджей YouTube
- Опционально: куки браузера для авторизации

**2. Извлечение кадров**
- OpenCV режет видео с шагом 6 секунд
- Сохранение в JPG с метаданными (таймкод, путь)

**3. Описание кадров (GigaChat Vision)**
- Двухуровневая стратегия: upload_file → base64 fallback
- Кэширование результатов после каждого кадра
- Инструкция: 2-3 предложения, только видимые объекты

**4. Чанкинг транскрипции**
- Разбиение по предложениям (3 предложения на чанк)
- Перекрытие: 1 предложение между чанками
- Расчёт примерных таймкодов пропорционально длительности видео

---

## СЛАЙД 6: Этап 2 — Индексация документов

**Векторный индекс (Dense)**
- GigaChat Embeddings создаёт векторные представления
- Chroma DB хранит эмбеддинги персистентно (SQLite)
- Метаданные: modality (text/frame), doc_id, таймкоды

**Спарс-индекс (BM25)**
- Токенизация: regex \b\w+\b (слова в нижнем регистре)
- BM25Okapi строит инвертированный индекс
- Эффективен для точных совпадений терминов, чисел, имён

**Структура документа:**
- Текст: {modality: 'text', start_time, end_time, chunk_id}
- Кадр: {modality: 'frame', timestamp, abs_path, caption}
- Файл пользователя: {modality: 'file', citation: 'File#'}

## СЛАЙД 7: Этап 3 — Поиск и генерация ответа

**Гибридный поиск с RRF (Reciprocal Rank Fusion)**
- Dense ranking: косинусное сходство в Chroma
- Sparse ranking: BM25 scores
- RRF формула: score = 1 / (k + rank), где k=60
- Преимущества: не требует нормализации скоров

**HyDE (Hypothetical Document Embeddings)**
- LLM генерирует гипотетический ответ (3-4 предложения)
- Гипотеза используется как дополнительный поисковый запрос
- Улучшает семантическое соответствие для абстрактных вопросов

**Генерация ответа (GigaChat-2-Max)**
- System prompt: строгое следование контексту
- Температура 0.2 для детерминированности
- Обязательные ссылки на источники [T#], [F#], [File#]

## СЛАЙД 8: Трудности — Технические проблемы

**Проблема 1: YouTube блокировки**

Симптомы: yt-dlp не может скачать видео из-за JS-челленджей

Решение:
- Установка Deno для выполнения JavaScript
- Флаг --remote-components ejs:github
- Альтернатива: экспорт cookies из браузера
- Fallback: работа только с транскрипцией

**Проблема 2: Vision API ошибки**

Симптомы: GigaChat Vision возвращает ошибки при загрузке изображений

Решение:
- Двухуровневая стратегия:
  1) upload_file() + file_id (предпочтительно)
  2) base64 кодирование в image_url (fallback)
- Кэширование после каждого успешного кадра
- Заглушки для неудачных попыток

---

## СЛАЙД 9: Трудности — Алгоритмические проблемы

**Проблема 3: Низкая релевантность поиска**

Симптомы: Dense-поиск пропускает точные термины и числа

Решение: Гибридный поиск
- Добавлен BM25 для keyword matching
- RRF объединяет ранжирования без нормализации
- Раздельные квоты на текст и кадры
- Фильтрация по modality для баланса

**Проблема 4: Абстрактные запросы**

Симптомы: Краткие вопросы ("Что будет с Арктикой?") дают слабый поиск

Решение: HyDE расширение
- Генерация гипотетического ответа перед поиском
- Гипотеза содержит больше контекстных слов
- Опционально (toggle в UI) из-за доп. вызова LLM

## СЛАЙД 10: Трудности — Интеграция и UX

**Проблема 5: Галлюцинации LLM**
- Решение: System prompt с явным запретом на выдумывание
- Ограниченный контекст (только найденные документы)
- Принудительное цитирование источников
- Низкая температура (0.2)

**Проблема 6: Отсутствие обратной связи по источникам**
- Решение: Теги [T#], [F#], [File#] в контексте и ответе
- Раскрываемые блоки с полным текстом фрагментов
- Превью кадров с таймкодами

**Проблема 7: Загрузка пользовательских файлов**
- Решение: RecursiveCharacterTextSplitter для чанкинга
- Приоритет чанков из файла (score=10.0)
- Предпросмотр чанков в sidebar
- Отдельный блок рендеринга для file context

## СЛАЙД 13: Вопросы для защиты и ответы

**Q: Почему гибридный поиск?**
A: Dense ловит семантику, BM25 — точные термины. RRF даёт лучшее покрытие без нормализации скоров.

**Q: Зачем HyDE?**
A: Абстрактные вопросы → гипотетический ответ с большим контекстом → лучше семантический match.

**Q: Почему GigaChat?**
A: Российская модель, работает в РФ, единый API для text/vision/embeddings, качественный русский язык.

**Q: Как боретесь с галлюцинациями?**
A: System prompt, ограничен контекст, цитирование [T#]/[F#], температура 0.2.

**Q: Масштабируемость?**
A: Достаточно положить новую транскрипцию и запустить prepare_data.py. Для prod — FastAPI + коллекции Chroma.

**Q: Как оцениваете качество?**
A: Субъективно: релевантность + корректность ссылок. Для объективной: Precision@K, Recall, NDCG (нужен размеченный датасет).

## ДОПОЛНИТЕЛЬНЫЕ ВОПРОСЫ (для заметок докладчика)

**1. Как обрабатываются ошибки Vision API?**
- Двухуровневая стратегия: upload_file → base64 fallback → заглушка
- Кэширование после каждого кадра

**2. Почему чанкинг по предложениям?**
- Семантическая целостность, удобство таймкодов, предсказуемый размер

**3. Что если токен GigaChat недействителен?**
- AuthenticationError 401. Получить новый в личном кабинете GigaChat B2B

**4. Какие ограничения у системы?**
- Нет автоматической ASR, один индекс, Streamlit не для high-load, нет кэша ответов

**5. Можно ли применить к другому видео?**
- Да: новая транскрипция + update YOUTUBE_URL + prepare_data.py --force
