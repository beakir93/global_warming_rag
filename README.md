# Мультимодальная RAG-система: глобальное потепление

Сервис отвечает на вопросы про глобальное потепление, опираясь на расшифровку
научно-популярного видео и ключевые кадры из него. Поверх данных построен
гибридный поиск (Dense + BM25, объединение через RRF) с опциональным
HyDE-расширением запроса. Описания кадров получены через GigaChat Vision,
эмбеддинги и генерация — через GigaChat. Интерфейс — Streamlit.

## Возможности

- Загрузка и обработка видео с YouTube, извлечение кадров с заданным шагом
- Описание кадров мультимодальной моделью GigaChat-2-Max
- Чанкинг транскрипции с привязкой к таймкодам
- Гибридный ретривер (Chroma + BM25, объединение Reciprocal Rank Fusion)
- HyDE-расширение запроса для абстрактных вопросов
- Чат-интерфейс на Streamlit с показом найденных кадров и текстовых фрагментов

## Запуск из готового пакета

В архиве уже лежат все артефакты: видео, кадры, описания кадров, готовый
векторный индекс и `.env` с ключом GigaChat. Достаточно поднять окружение
и запустить интерфейс — ничего перекачивать не надо.

```bash
python3.12 -m venv .venv
source .venv/bin/activate
pip install --upgrade pip
pip install -r requirements.txt

streamlit run app.py
```

Откроется на `http://localhost:8501`. Спрашивайте в чате — в ответах появятся
ссылки `[T#]` (фрагменты транскрипции) и `[F#]` (кадры с таймкодами).

### Требования

- **Python 3.12** (на 3.13 ещё нет колёс под часть зависимостей; на 3.10/3.11
  тоже соберётся, но 3.12 проверен).
- macOS / Linux. На Windows должно работать, но `yt-dlp --cookies-from-browser`
  и пути с обратными слэшами не тестировались.
- Доступ к интернету для GigaChat API.

## Пересборка данных (опционально)

Если хочется пересобрать всё с нуля или применить систему к другому видео,
есть пайплайн `prepare_data.py`. Для этого нужен JS-рантайм для yt-dlp:

```bash
brew install deno                            # macOS
# или: curl -fsSL https://deno.land/install.sh | sh

python prepare_data.py --force --cookies-from-browser chrome
```

Скрипт сделает следующее:

1. `yt-dlp` скачает видео из YouTube (`--remote-components ejs:github`
   подтянет EJS-решатель для JS-челленджей, нужны куки браузера).
2. `opencv-python` нарежет кадры с шагом `FRAME_INTERVAL_SEC` секунд.
3. Каждый кадр → GigaChat Vision → русское описание (кэшируется в
   `data/captions.json`, безопасно прерывать).
4. Транскрипция разрежется на чанки с примерными таймкодами.
5. Тексты и описания кадров уложатся в Chroma + BM25.

Без флага `--force` скрипт пропускает уже выполненные этапы — можно
дозапускать.

### Транскрибация

**В пайплайне её нет.** Скрипт ожидает готовый `data/transcript.txt`. Для
демо-сборки транскрипция видео про глобальное потепление уже лежит в этом
файле. Если будете применять систему к другому видео — придётся либо
прогнать аудио через Whisper / GigaChat Audio самостоятельно, либо просто
вписать в `data/transcript.txt` нужный текст.

### Что делать, если YouTube ругается

YouTube блокирует автоматизированные скачивания. После `brew install deno`
ещё может потребоваться скачать EJS-скрипт (yt-dlp подтянет его сам при
флаге `--remote-components ejs:github`, уже включён в коде).

Альтернатива через файл с куками (без `--cookies-from-browser`):

1. Поставьте расширение **Get cookies.txt LOCALLY** в Chrome.
2. На странице `youtube.com` экспортируйте куки в файл.
3. ```bash
   yt-dlp --cookies cookies.txt --extractor-args "youtube:player_client=tv" \
     -f "best[ext=mp4]/best" -o data/video.mp4 https://youtu.be/WXUINIDj5qI
   python prepare_data.py
   ```

Если и так не получается — `prepare_data.py` всё равно соберёт индекс из
одной транскрипции, но без визуальной модальности.

## Структура

```
data/
  transcript.txt    # расшифровка видео (предоставляется на входе)
  video.mp4         # исходное видео
  frames/           # извлечённые кадры (jpg)
  captions.json     # описания кадров от GigaChat Vision
  index_meta.json   # сводка по индексу
chroma_db/          # персистентное векторное хранилище
src/
  config.py         # пути, модели, гиперпараметры
  llm.py            # фабрики GigaChat (LLM, Vision, Embeddings)
  ingest.py         # загрузка видео, нарезка кадров, чанкинг
  captions.py       # описание кадров через GigaChat Vision
  retriever.py      # сборка документов, Chroma + BM25 + RRF
  rag.py            # HyDE + генерация ответа со ссылками на источники
prepare_data.py     # пайплайн подготовки данных
app.py              # Streamlit-сервис
requirements.txt    # фиксированные зависимости
.env                # ключ GigaChat и параметры моделей
```

## Архитектура

1. **Подготовка данных** (`prepare_data.py`)
   - `yt-dlp` скачивает видео из YouTube
   - `opencv-python` режет видео на кадры с шагом `FRAME_INTERVAL_SEC`
   - Каждый кадр уходит в GigaChat Vision (attachment, при сбое — fallback
     на base64 image_url) и получает короткое описание
   - Транскрипция режется на чанки по предложениям, каждому чанку
     присваиваются примерные таймкоды
   - Тексты и описания кадров складываются в один Chroma-индекс
     с метаданными `modality = text | frame`

2. **Поиск** (`src/retriever.py`)
   - Dense: GigaChat Embeddings + Chroma
   - Sparse: BM25 поверх токенизированных документов
   - Объединение через Reciprocal Rank Fusion (`k = 60`)
   - Поддерживается фильтрация по модальности и квоты на текст/кадры

3. **Генерация** (`src/rag.py`)
   - HyDE: модель пишет короткий гипотетический ответ, который участвует в
     поиске вместе с исходным вопросом
   - LLM получает контекст с тегами `[T#]` (текст) и `[F#]` (кадр) и
     обязана ссылаться на них в ответе

4. **Интерфейс** (`app.py`)
   - Чат с историей, превью кадров, раскрываемые блоки с источниками
   - Сайдбар: настройка `top-K`, квот, HyDE; статистика индекса; превью видео

## Параметры

`src/config.py` хранит ключевые настройки:

| Параметр | Значение | Назначение |
|---|---|---|
| `FRAME_INTERVAL_SEC` | 6 | Шаг между извлекаемыми кадрами |
| `CHUNK_SIZE` / `CHUNK_OVERLAP` | 380 / 80 | Резерв для перехода на символьный чанкинг |
| `DEFAULT_TOP_K` | 5 | Базовый размер контекста |
| `DEFAULT_RRF_K` | 60 | Константа RRF |

## Переменные окружения

Уже заполнены в `.env`, переопределять не обязательно:

| Имя | Назначение |
|---|---|
| `GIGACHAT_CREDENTIALS` | Base64-ключ авторизации GigaChat |
| `GIGACHAT_SCOPE` | По умолчанию `GIGACHAT_API_B2B` |
| `GIGACHAT_MODEL` | LLM, по умолчанию `GigaChat-2-Max` |
| `GIGACHAT_VISION_MODEL` | Vision-модель, по умолчанию `GigaChat-2-Max` |
| `YOUTUBE_URL` | Источник видео |

## Замечания

- Описания кадров требуют доступа к мультимодальному GigaChat. Если квот нет,
  индекс соберётся только из текста — поиск продолжит работать, но без
  визуальных подсказок.
- Видео и кадры не лежат в индексе как бинарь — в Chroma хранятся только
  описания и метаданные с путями к файлам.
- `.env` содержит реальный ключ GigaChat — не публикуйте архив в открытых
  репозиториях.
